# Dependency Intake Procedure

1. Document the business need.
2. Record alternatives evaluated, including no-new-dependency option.
3. Review project health, maintenance cadence, release history, and community signals.
4. Review license expression and notice obligations.
5. Review maintainers and package ownership signals.
6. Check known vulnerabilities and advisories.
7. Inspect download/install/postinstall scripts.
8. Assess transitive dependency risk.
9. Identify data collection behavior.
10. Identify telemetry defaults and opt-out controls.
11. Review runtime permissions and server/client exposure.
12. Commit lockfile change with package manifest change.
13. Regenerate license inventory and SBOM.
14. Obtain approval from designated reviewer(s).
15. Document rollback command/path.
16. Record replacement plan for abandonment, license conflict, or security issue.
