# 03 — SaaS Readiness Scorecard

Scale: 0 (absent) – 5 (enterprise-grade). Each score is justified with real paths, not aspiration. Scores reflect the *real core product* (see `04-critical-findings.md` / product domain inventory) — the speculative "constitutional/governance/twin" layer is scored separately where it materially affects a dimension (e.g. AI governance).

| Dimension | Score | Justification |
|---|---:|---|
| Product readiness (core PM/PMO) | 3/5 | Projects/programs/portfolio/critical-path/RAID/execution-tasks/dashboard are real, DB-backed, and reachable via `NAVIGATION_HIERARCHY`. AI chat is genuinely wired (`playbook-engine` → `/api/command-center/chat`). Held back by: PMO Command Center and PM Registry/Performance/Capacity are real code but **orphaned from navigation** (unreachable without knowing the URL), and the "AI first insight" onboarding moment is a scripted animation, not a model call. |
| B2C readiness | 2/5 | Signup→onboarding→first-project genuinely persists to Postgres. Blocked by: no Terms of Service/Privacy Policy at all (only disabled footer links), zero product analytics, no account deletion/export, no OAuth login. |
| B2B readiness | 2/5 | Workspace/role/invite model is genuinely mature (`workspace-access.ts`, hashed invite tokens, owner-safety rules) — best-in-class for this stage. Blocked by: no SSO/MFA, no owner-transfer flow, one known unfixed RLS policy bug (`governance_delegations` references non-existent table), no support/admin console beyond founder-only tooling. |
| Enterprise readiness | 1/5 | No SCIM, no SSO, no SLA definition, no assurance tier, no external AOC-backed identity/trust story (PMFreak currently self-implements what an enterprise buyer would expect from an external, audited identity/trust provider). |
| Multi-tenancy | 4/5 | 408/409 tables have RLS; a real cross-tenant recursion bug was caught and fixed (`20260823000001_fix_workspace_memberships_rls_recursion.sql`); live two-workspace SQL isolation tests pass 10/10. Docked for: 2 tables still on legacy `company_id` isolation, one named unfixed RLS bug, and at least one API route (`vault/intake`) that relies on RLS alone rather than app-layer + RLS defense-in-depth. |
| Auth | 3/5 | Password auth, email verification, password reset, logout, session management all real and rate-limited. No OAuth/social login, no MFA — meaningful gaps for both B2C conversion and B2B credibility. |
| Authorization | 4/5 | Role model (`owner/admin/pm/viewer`) is server-enforced from `workspace_memberships`, never from client-controlled display role. Five security docs each document a real historical vulnerability and its fix, verified to match current code. Docked for the one known unfixed RLS typo and the absence of granular custom roles. |
| Billing | 3/5 | Stripe webhook trust boundary, idempotency, and role-based checkout authorization are genuinely hardened (exceeds typical early-stage rigor). Docked for: no coupons, no tax handling, no native Stripe trials, no invoice/dunning UI, hardcoded (not DB-driven) plan catalog. |
| Metering/usage | 2/5 | Real AI cost/request ceilings exist per-workspace with atomic upload-quota reserve/commit RPCs. Not customer-facing usage billing — no metered Stripe pricing, no usage dashboard, cost estimation covers only 5 hardcoded models, and the cost ceiling fails open on accounting-read failure. |
| Security | 3/5 | Independently verified: no secret leakage, no service-role exposure to client, real security headers/CSP, real rate limiting, dependency audit clean (0 critical/high). Docked for: two open pilot-blocking release risks (no hosted-DB migration proof, no rehearsed backup restore), no pentest yet, and a newly-found raw-Postgres-error-message leak across ~10 authenticated SDK/governance routes. |
| Observability | 2/5 | Real structured, redacting logger; real `/api/ready` and `/api/health` checks. No external error-tracking/alerting platform (Sentry/Datadog-class) — monitoring is log/audit-table-based only, explicitly acknowledged as not scaling past a hand-supervised pilot. |
| Reliability | 2/5 | Fail-closed abuse protection and env-safety checks are real. No rehearsed disaster recovery, no confirmed hosted-DB migration path, single-author/no independent review of the extensive self-certification suite. |
| Compliance | 0/5 | No Terms of Service, no Privacy Policy, no DPA, no subprocessor list, no AI-disclosure page exist anywhere in the repo or public assets — only disabled UI placeholders. This is a hard blocker to charging any customer. |
| AI governance | 2/5 | Real guardrails exist for the *actual* AI surface (chain-depth limits, per-workspace concurrency, circuit breaker, egress/data-sensitivity policy, cost ceilings, approval-gated tool risk levels). Scored down because the much larger "constitutional/governance/sovereign" layer uses governance vocabulary while being functionally inert (hardcoded topology, in-memory-only tool execution with side effects disabled) — a genuine risk if presented to a buyer evaluating AI governance claims. |
| AOC consumer readiness | 1/5 | No external AOC provider exists to consume yet, and PMFreak currently *is* the canonical implementer of identity/claims/attestation/revocation/trust-domain logic that the governing brief says must be externally owned. Real preparatory work exists (ports, adapters, dependency-direction lint, extraction plan docs) but the only working authority-provider path is in-process; external modes are unimplemented stubs. |
| Supportability | 1/5 | Founder-only early-access dashboard is real (invite/trial management) but there is no general customer/org lookup, no impersonation, no ticketing, no billing-credit tooling. Fine for founder-led pilot; not for scaled support. |
| Transferability | 2/5 | Single-author repo (100% one committer per `git log`) with a large, self-authored, self-tested "governance" layer that would require significant due-diligence effort by a new owner or acquirer to separate real from speculative. Strong upside: the real core is well-isolated by directory and reasonably tested. |
| Valuation defensibility | 2/5 | The real, sellable core (multi-tenant PM/PMO + billing + AI chat) is defensible on its own. Valuation risk comes specifically from the scaffolding layer's self-congratulatory documentation ("no fabricated insights," "governance boundaries") describing code that returns hardcoded data or writes to in-memory maps — this would need to be disclosed and separated before any investor or acquirer diligence, or it reads as misrepresentation. |

## Composite read

The product and its tenant-isolation/security fundamentals are stronger than the median pre-seed SaaS. The gap to a fundable, sellable, chargeable SaaS is concentrated in exactly five places: **legal/compliance (0/5, hard blocker)**, **AOC consumer readiness (1/5, mandate-defining)**, **supportability (1/5)**, **enterprise readiness (1/5)**, and the **credibility risk of the scaffolding layer** that depresses AI governance and valuation defensibility scores despite real guardrails existing for the actual AI surface in use.
